## 已冻结技术决定

- 目录：后端统一在 `backend/`，PC前端统一在 `frontend/`；不得再增加 `server/`、`admin-web/` 等项目级嵌套目录。
- 后端：Java 21、Spring Boot 3.5、Spring Security、Spring Session JDBC、MyBatis、Flyway。
- PC前端：Vue 3、TypeScript、Vite、Element Plus、Pinia、Vue Router。
- 数据库：SQL Server 2022；旧库只读，新库只允许Flyway修改。
- 架构：单仓库、前后端分离、模块化单体；首月不拆微服务。
- 金额：Java使用BigDecimal，数据库使用 `decimal(19,4)`，禁止float/double。
- 资产：储值、积分、次卡、库存、提成使用“当前余额/快照＋不可变流水”。
- 调账和冲销：生成反向流水，不覆盖原交易。
- 换卡：按原办卡单价折算剩余价值，只允许目标售价不低于余值；报价锁定原卡和目标卡种版本，成功后原卡关闭并建立新卡及双向流水。
- 转赠：整张转移剩余资产，原卡关闭，接收会员新卡的办卡金额和总次数重置为剩余价值和剩余次数，保持后续单位价值连续。
- 退卡：按有效消费账单行的项目原价重计；提交后冻结，驳回恢复，审批执行后清零并记录退款。提成未实际冲回时必须保持PENDING_MODULE。
- 代金券：模板与券码实例分离，券码保存发放规则快照；确认结算才核销，整单冲销按原核销流水返券，不允许脱离账单直接核销。
- 提成：方案修改递增规则版本并保留revision；业务流水只追加且保存公式快照；无规则必须进入`PENDING_RULE`，冲销追加关联原流水的负数记录。
- 转赠提成：转赠不产生新售卡提成；后续换卡/退卡通过`transfer_from_card_id`查找最近的原售卡事实并追加负向流水。
- 回访：会员账单结算后同事务生成一张任务，每位服务技师一个参与项；全部完成后任务完成，整单冲销只取消未完成任务。到期小时读取`VISIT/AFTER_SALE_DUE_HOURS`，默认24，只影响新任务。
- 服务反馈：只有人工明确勾选客诉的回访记录才自动建单；反馈按待处理、处理中、已解决、已关闭流转，所有处理动作追加历史；建单/重开保存可配置时限快照，当前只做页面超时提示，不虚构主动消息推送。
- 满意度规则：按优先级执行可解释的字面关键词匹配，同规则内长词优先；未命中不推断，样例试算不写业务数据，正式规则由甲方审核录入。
- 会员主档：资料、状态和标签操作均提交`rowversion`；手机号不回显原文，冻结原因写独立历史；归属门店禁止在普通编辑中直接修改。
- 会员归属：申请与审批/执行分离；同日审批立即生效，未来申请由SQL Server运行档到期领取；只改当前归属并清空旧顾问，历史单据不回写。
- 批量会员：当前只处理页面明确勾选的1~100人，逐条事务并返回成功/跳过/失败；手工和批量顾问变更都必须保存前后值，筛选全客群由后续任务中心执行。
- 文件：对象键由服务端生成且不对业务端返回；`sys_file_object`保存摘要，`sys_file_attachment`限定业务归属；业务权限校验后才能下载，删除先软删除，物理清理由保留期任务处理。
- 异步任务：`sys_async_job`保存请求和执行状态，SQL Server用跳锁方式单次领取；任务查询和下载按创建人隔离，结果复用私有文件服务并默认7天过期。
- 会员导出：固定任务创建时当前门店，使用独立`member:member:export`权限；CSV只包含脱敏手机号，不提供明文导出开关。
- 首个纵向样板：登录→当前用户→门店→角色权限→工作台。
