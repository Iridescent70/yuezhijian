# ITER-41 员工与工位资料维护

## 目标

补齐预约主数据中的员工和工位编辑能力，支持在离职、启停等日常维护，并避免并发覆盖及跨门店越权。

## 已实现

- 员工新增支持入职日期；新增员工详情和更新接口，维护姓名、可选新手机号、职务、主门店、入离职日期、服务/销售能力及状态。
- 员工号创建后不可修改；完整手机号不回显，编辑时留空保留原加密值，主动填写新手机号才重建密文、检索哈希和后四位。
- 员工状态限定`ACTIVE/DISABLED/LEFT`；离职必须填写离职日期，非离职不得保留离职日期，离职日期不得早于入职日期。
- 工位新增详情和更新接口，维护名称、容量、排序及`ACTIVE/DISABLED`状态；工位编号和所属门店创建后不可修改。
- 两类更新均使用现有SQL Server `row_version`乐观锁；旧版本提交返回409冲突，memory运行档保持同样行为。
- 员工和工位详情、原门店及目标门店均经过后端数据范围校验；页面增加编辑入口、状态展示和日期字段。

## 验证范围

- 接口测试覆盖员工手机号脱敏保留、离职资料更新、工位停用、版本冲突及详情回查。
- 数据范围测试覆盖门店角色不得读取其他门店员工、工位详情。
- Mapper测试确认员工和工位更新均带`row_version`并记录操作人。
- `make verify`通过：后端129项测试、前端2项测试、类型检查和生产构建全部成功；Compose配置检查通过。
- 本迭代不新增表或字段，直接复用既有Migration中的入离职日期、状态和`row_version`。

## 明确限制

- 本迭代是基础资料维护，不包含员工跨店借调、耗损导入和独立变更历史页面。
- 职务维护及默认提成规则尚未开发；当前只能选择已启用职务。
- 员工手机号暂不提供清空操作，避免空输入误删；需要变更时填写完整新号码。
