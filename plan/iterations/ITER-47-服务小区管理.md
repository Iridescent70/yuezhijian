# ITER-47 服务小区管理

## 目标

落实系统管理-30、优化系统管理-03和到家服务-02的服务小区维护，为后续到家报价和派单提供可信的门店服务范围、中心坐标、半径和上门费基础数据。

## 已实现

- 查询条件覆盖授权门店、城市/区域/地址关键词和状态；列表展示门店、坐标、半径、上门费、操作人和操作时间。
- 总部和店长可在各自门店范围内新建、编辑、启用和停用；详情、列表和写入均执行后端门店数据范围校验。
- 门店归属创建后固定，避免已有到家业务范围跨店漂移；误建记录应停用后在正确门店重建。
- 同门店地址唯一；经纬度、半径、费用、状态同时由Bean Validation和SQL Server约束校验。
- 编辑使用rowversion，过期提交返回冲突，不静默覆盖其他人的修改。
- 成功新建和修改与业务数据同事务写入统一操作日志，保存门店、地址、坐标、半径、费用和状态前后值。

## 验证范围

- HTTP流程：新建、门店/关键词/状态筛选、编辑停用、过期版本冲突、重复地址和审计查询。
- 数据范围：店长本店查询成功，跨店列表、详情和新建均返回`40301`。
- Mapper：动态筛选参数、操作人关联、rowversion读取及乐观锁更新SQL解析。
- 前端：类型检查、测试和生产构建纳入`make verify`。

验证结果：后端140个测试全部通过，前端2个测试、类型检查、生产构建和Compose配置检查通过；最大公共JS约176.11 KB。

## 数据库与发布

- Migration：`V202607291450__init_service_area_management.sql`。
- 发布后抽查门店+地址唯一约束、角色权限、操作日志和启停状态；不得手工改库绕过门店范围。
- 停用记录不删除，为后续到家订单保存稳定的`service_area_id`引用。

## 明确限制

- 当前只完成可信的服务范围主数据，不宣称完成到家订单报价、距离计算或派单流程。
- 地图Key、域名白名单和测试额度尚未提供，因此地图选点、地址解析和可视化范围预览未作假联调；页面明确提示并支持人工录入坐标。
- 后续距离校验必须统一后端算法和地图坐标系，不允许仅依赖前端判断服务范围。
- SQL Server实表Migration、约束和事务回滚仍等待本地Docker权限恢复后验证。
