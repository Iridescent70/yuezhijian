## 一、迭代目标

在不丢失 `main@6cae2c8` 已完成业务、文档和数据库规则的前提下，引入芋道 Vue3 管理端作为新 PC 前端底座，并建立可以连接悦指间现有后端的登录、权限、菜单、工作台和工程构建基线。

## 二、范围

### 本期范围

| 需求编号 | 功能 | 确认方 | 前置条件 | 验收场景 |
| --- | --- | --- | --- | --- |
| REF-P0-01 | 导入芋道前端并记录上游版本 | 项目组 | `main` 基线冻结 | 新分支可追溯上游提交，原前端和文档仍可访问 |
| REF-P0-02 | 适配 Spring Session、CSRF 和统一响应 | 项目组 | 现有认证 API | 登录、写请求、当前用户和退出使用现有后端协议 |
| REF-P0-03 | 适配权限菜单和真实工作台 | 项目组 | `/auth/me`、工作台 API | 用户菜单转为动态路由，未迁移页面显示迁移提示 |

### 非本期范围

- 不在本迭代迁移 `main` 的全部业务页面。
- 不用芋道示例后端替换悦指间的金额、权益、库存、提成或门店数据范围规则。
- 不提交本地 `ref/legacy-source/` 中的甲方历史源码。
- 真实浏览器联调和各业务模块页面迁移在后续任务继续完成。

## 六、发布与回滚

1. 发布版本：重构分支开发基线，不直接发布生产。
2. 数据库迁移：无。
3. 发布步骤：安装锁定依赖、构建前端、部署现有后端和前端静态资源。
4. 冒烟用例：登录、工作台、动态菜单、未迁移提示、退出、会话过期。
5. 回滚触发条件：认证或菜单无法联调，或关键文档/业务资产缺失。
6. 回滚步骤：生产保持 `main`；开发侧可切回 `main`，原前端也保存在快照目录。
