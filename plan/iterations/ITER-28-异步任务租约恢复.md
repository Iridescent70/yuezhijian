# ITER-28 异步任务租约恢复

## 目标

解决服务重启或执行节点异常后任务永久停在“执行中”的问题，同时阻止已失去任务所有权的旧节点覆盖新节点结果。

## 已实现

- 任务领取时生成唯一`lease_token`，写入租约到期时间并递增`attempt_count`。
- 执行期间由独立守护线程按租约三分之一周期续租，默认租约30分钟。
- 待处理任务和租约过期任务都使用SQL Server `UPDLOCK + READPAST + ROWLOCK`原子领取，多实例不会领取同一次尝试。
- 完成、失败和续租都必须匹配任务id与租约令牌；任务被新节点重领后，旧节点不能再写最终状态。
- 节点失联任务最多领取3次，最后一次租约仍过期时自动标记失败并写入可读原因。
- 新增`JOB_LEASE_MINUTES`和`JOB_MAX_ATTEMPTS`配置，最大领取次数在应用层限制为10。

## 验证范围

- 内存仓库测试覆盖租约过期重领、旧令牌失效、当前令牌续租和达到次数后失败。
- Mapper SQL结构测试覆盖跳锁、过期条件、领取次数递增及完成操作的令牌条件。
- 会员与服务反馈导出接口回归通过。
- `make verify`通过：后端105项测试、前端2项测试、类型检查和生产构建全部成功；Compose配置检查通过。

## 明确限制

- 当前重试只针对执行节点失联；处理器主动抛出的确定性业务错误会直接失败，避免无意义重复执行。
- SQL Server真实多实例并发和进程强杀恢复仍需在Docker/测试环境做故障演练。
- 任务结果文件过期后的物理清理、错误明细文件和大文件流式生成仍未实现。
