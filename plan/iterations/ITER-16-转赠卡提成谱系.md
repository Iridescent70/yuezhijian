# ITER-16 转赠卡提成谱系

## 目标

使用现有`ast_member_card.transfer_from_card_id`追溯转赠卡的来源卡，保证转赠后换卡或退卡仍能准确冲回原售卡提成。

## 已实现

- 内存档和SQL Server档都能按“当前卡 → 上一张转赠卡”向上查询，最多32层并防止异常循环。
- 换卡和退卡优先查找当前卡的售卡事实；没有时再沿转赠谱系查找最近的原始售卡事实。
- 负向流水的`source_line_id`保存实际换卡/退卡的当前卡，`reversed_ledger_id`关联谱系中的原提成流水。
- 转赠卡的售卡员工也沿谱系查询，有原始售卡员工但缺规则时保持待处理，不会误标为无需冲回。
- 不新建谱系表，不增加Migration，不改变现有转赠API和页面交互。

## 已验证

- 自动化覆盖“售卡 → 连续转赠两次 → 退卡”，退卡正确生成`-64.0000`提成并关联原`64.0000`售卡流水。
- 自动化确认退卡流水指向最终接收人的当前卡，退卡提成状态为`COMPLETED`。
- 自动化覆盖“售卡 → 转赠 → 换卡”，旧售卡提成`-64.0000`、新卡补差提成`70.0000`均正确。
- SQL Mapper契约测试覆盖递归CTE、父卡连接、深度限制和售卡员工追溯。
- `make verify`通过：后端66项测试、前端类型检查、2项单元测试和生产构建全部成功；最大公共JS约169.01 KB。

## 明确限制

- 转赠本身不新增或重新分配售卡提成。
- 谱系只用于转赠来源；换卡已单独冲回旧卡并建立新卡补差提成，不再回溯已冲回的旧卡。
- 真实SQL Server镜像未就绪，递归CTE已做Mapper契约验证，仍需在数据库档环境补充实际执行验证。
