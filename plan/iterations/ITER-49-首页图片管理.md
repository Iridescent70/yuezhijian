# ITER-49 首页图片管理

## 目标

落实系统管理-32，完成首页图片上传、配置、有效期控制、工作台展示和审计闭环，并复用既有私有对象存储能力。

## 已实现

- 总部管理页支持按位置、名称和状态查询，上传JPG/PNG/WEBP，新建、编辑、换图、排序、有效期和启停。
- 图片正文只进私有对象存储，数据库保存文件引用；接口不暴露对象键，读取时复核权限、文件用途、状态和SHA-256。
- 配置和换图使用rowversion；新图在事务回滚时注册对象清理，替换成功后旧文件软删除，避免继续通过业务接口访问。
- 跳转分无跳转、站内页面和站外HTTPS；后端拒绝双斜线站内地址、HTTP地址和带用户凭据的站外URL。
- PC工作台并行加载当前有效图片，图片服务失败不阻断经营指标；支持站内路由及安全新窗口跳转。
- 活动列表使用最小DTO，不返回文件ID、操作人等管理字段；停用和非有效期图片的活动图片接口返回404。

## 验证范围

- HTTP闭环：上传、活动列表/图片读取、元数据编辑、不安全链接拒绝、换图、停用、过期版本和操作日志。
- 文件：文件头/扩展名/用途、摘要读取、旧文件退役和非图片拒绝。
- Mapper：管理筛选、有效期SQL、文件状态、操作人和两类rowversion更新。
- 前端：类型检查、测试、生产构建和工作台降级纳入`make verify`。

- 发布后至少用PC工作台跑通一张无跳转图和一张站内跳转图，并验证开始/结束边界、停用和换图缓存刷新。

## 明确限制

- 合同只要求展示位置，当前基线为PC工作台和到家首页；到家客户端尚未开发，因此只完成其配置位置，未宣称到家展示完成。
- 合同未确认宽高比、最小像素、裁剪锚点和多端响应式素材规则，当前不强制裁剪；规则确认后再增加图片解码/重编码流程。
- 旧图片只软删除元数据，实际物理对象等待后续统一孤儿/保留期清理，避免事务回滚造成有效引用丢失。
- SQL Server实表Migration、约束、事务回滚及真实MinIO仍等待本地Docker权限恢复后验证。
