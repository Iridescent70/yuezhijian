## 一、目标

在空白开发机上用统一命令启动SQL Server、后端和前端，并通过Flyway从空库创建第一版结构。7月31日前至少跑通“登录—门店—角色权限”的纵向样板，为会员、预约和结算开发提供同一套工程基线。

## 二、本期工作

1. 安装Java 21，切换Node.js 24，确认Docker权限和端口占用。
2. 按技术实施计划建立 `backend/` 后端、`frontend/` PC端、接口契约、测试、迁移和部署目录。
3. 使用Compose启动SQL Server 2022 Developer和MinIO，Redis先保留可选profile。
4. 接入Flyway和微软JDBC驱动，建立数据库版本查询、校验和升级命令。
5. 创建首批Migration：迁移审计表、用户角色权限、公司门店和操作日志。
6. 从旧Hibernate映射整理会员、会员资产、预约和账单核心表对应关系。
7. 建立一次空库升级测试和一次“上一版本升级到当前版本”测试。

本迭代不开发会员、预约、开单和结算业务页面，也不导入甲方正式数据。

## 四、执行顺序

| 顺序 | 任务 | 验证命令/证据 |
| ---: | --- | --- |
| 1 | 检查本机环境 | `make doctor` |
| 2 | 初始化项目目录和依赖 | `make bootstrap` |
| 3 | 启动SQL Server和MinIO | `make infra-up`、容器健康检查 |
| 4 | 创建本地数据库和应用账号 | `make db-init` |
| 5 | 启动数据库版后端，由Flyway执行全部Migration | `make backend-dev-db`、检查 `flyway_schema_history` |
| 6 | 启动前端 | `make frontend-dev`、访问登录页和工作台 |
| 7 | 执行后端和前端自动化测试 | `make test` |
| 8 | 完成整体验证 | `make verify` |

## 五、完成标准

- 新开发者只需准备 `.env.local`，即可按上述命令启动项目。
- SQL Server容器重启后数据仍保留，旧库和新库账号权限分开。
- 空库可通过Migration完整建成，`flyway validate`无错误。
- 修改已执行SQL会被校验值检查拦截，禁止绕过Flyway改共享库。
- 登录、门店和权限样板在测试环境跑通，并有接口、数据库和测试记录。
- 旧源码和甲方数据不进入Git仓库，日志中不出现密码、Token或完整敏感数据。
