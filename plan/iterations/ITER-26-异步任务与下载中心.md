# ITER-26 异步任务与下载中心

## 目标

把预留的`sys_async_job`落成可运行的任务中心，并用“当前门店服务反馈CSV导出”验证创建、后台领取、结果入库、查询、取消和私有下载全链路。

## 已实现

- 任务按创建人隔离；列表、详情、取消和结果下载都重新校验当前登录用户，不使用前端传入的创建人。
- 任务通过`PENDING → RUNNING → SUCCEEDED/PARTIAL/FAILED`状态流转，只有`PENDING`可取消；SQL Server领取使用`UPDLOCK + READPAST + ROWLOCK`避免重复消费。
- 单用户最多同时保留3个等待或执行任务；调度器每次最多领取5项，默认每2秒轮询。
- 服务反馈CSV固定导出当前门店，可按状态和是否超时筛选；手机号保持脱敏，文本统一CSV转义并阻断Excel公式注入。
- 结果文件复用私有文件服务，保存SHA-256，不返回对象键；下载校验任务创建人、成功状态、7天有效期和文件完整性。
- PC端新增`/app/system/downloads`，支持新建导出、状态筛选、自动刷新、任务详情、等待任务取消和结果下载。

## 验证范围

- 接口流覆盖任务创建、人工触发执行、列表、详情、CSV下载、取消及取消后禁止下载。
- 单元测试覆盖CSV公式注入防护、文件结果存储和SQL领取/创建人隔离条件。
- `make verify`全量通过：后端102项测试、前端类型检查、2项单元测试和生产构建均成功。
- SQL Server真实Migration、并发领取和MinIO结果文件仍需在Docker权限就绪后联通验证。

## 明确限制

- 当前只有服务反馈CSV处理器；会员/商品导入导出、错误文件、短信和AI任务后续按同一处理器接口接入。
- 进程在任务进入`RUNNING`后异常退出时，暂未自动识别和重置超时任务，须在生产调度迭代增加租约/心跳和人工重跑。
- 到期结果当前在接口层禁止下载，物理对象和元数据的保留期清理任务尚未实现。
- 当前CSV在内存中一次性生成且受10 MiB结果上限保护；大数据量导出需改为游标读取和流式写对象存储。
