# ITER-35 服务项目编辑与上下架

## 目标

补齐服务项目单条维护能力，让门店在预约和开单前可以修改项目名称、分类、时长、成本、标准价、门店价及上下架状态，并为后续CSV导入复用同一套校验和写入规则。

## 已实现

- 新增`GET /api/v1/services/{id}`，返回项目基础资料、全部有权门店配置和`rowversion`；门店账号不会看到其他门店价格。
- 新增`PUT /api/v1/services/{id}`，支持基础资料、启停状态以及指定门店价格和销售状态更新。
- 项目基础资料会影响所有适用门店；发生基础资料变化时，账号必须拥有该项目全部门店权限。只调整本店价格或上下架时只要求本店权限。
- SQL Server更新使用`cat_service.row_version`防止并发覆盖，项目主表和`cat_item_store`门店配置在同一事务提交。
- memory运行档同步支持详情、更新、门店配置和版本冲突，行为与SQL Server档一致。
- 服务项目页面默认当前会话门店，新增编辑入口，可切换有权门店配置并维护价格、在售/下架和项目启停状态。
- 本轮复用现有`cat_service`和`cat_item_store`，不新增Migration。

## 验证范围

- 新增接口测试覆盖项目详情、资料及门店价格更新、下架和旧版本冲突。
- 新增Mapper测试确认SQL更新带`row_version`条件，门店配置按项目类型、项目和门店三项定位。
- 门店范围测试补充跨店服务详情拒绝。
- `make verify`通过：后端115项测试、前端2项测试、类型检查、生产构建和Compose配置检查全部成功；最大公共JS约172.44 KB。

## 明确限制

- 本轮只维护现有门店配置，不增加或删除项目适用门店；跨店增配需要单独的门店配置变更接口和审核规则。
- 服务标签、物料消耗和批量处理尚未实现，API-CAT-009仍属于部分完成。
- 服务CSV导入将在下一迭代调用同一服务校验，不能直接绕过服务层批量写库。
