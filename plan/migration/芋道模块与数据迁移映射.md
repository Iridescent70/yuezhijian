# 芋道模块与数据迁移映射

更新时间：2026-07-30。

## 1. 使用边界

本文把 `main@6cae2c8` 的已实现代码、44 个 Migration 和未完成功能计划，映射到新的芋道全栈底座。它用于确定代码落点和迁移顺序，不代替甲方旧库的真实字段字典。

- 平台通用能力优先使用芋道现有模块，避免维护第二套用户、权限、文件、任务和支付框架。
- 门店业务规则进入独立的 `yudao-module-yuezhijian`，不侵入 `system`、`infra` 内核。
- main 表名是迁移资产，不是新库最终表名；旧脚本不得直接重放。
- 旧系统实体只有在取得数据库备份并核对数据类型、金额单位、行数和样例后才能定稿。

## 2. 平台模型映射

| main 资产 | 芋道目标 | 处理方式 | P1 必验 |
| --- | --- | --- | --- |
| `iam_user` | `system_users` | 用户名、密码不能直接复制；建立旧 ID 映射，按账号状态迁移并强制首次改密 | 登录、停用、重置密码、Token 失效 |
| `iam_role`、`iam_user_role` | `system_role`、`system_user_role` | 角色编码建立映射；不沿用 main 主键 | 总部/店长/员工角色 |
| `iam_permission`、`iam_menu` | `system_menu` | 权限码按芋道菜单/按钮模型重建，旧 `/api/v1` 不保留 | 动态菜单、按钮权限、接口鉴权 |
| `org_organization`、`org_store` | `system_dept` + 悦指间门店扩展表 | 集团/区域/门店使用部门树；地址、营业状态、门店编码等业务字段放扩展表 | 总部看全部、门店只看授权范围 |
| `org_position` | `system_post` | 岗位复用；职级、提成角色等业务属性放扩展表 | 岗位启停和员工绑定 |
| `org_employee` | `system_users` + 员工档案表 | 登录身份与员工业务档案拆分；保留在职状态、所属门店和服务能力 | 调店、离职、隐私字段权限 |
| `iam_role_store_scope` | 芋道角色数据范围 + 部门数据权限 | 转换为全部/本部门/本部门及以下/自定义部门；额外门店范围用关联表补充 | 查询与导出范围一致 |
| `sys_parameter`、`sys_dictionary` | `system_config`、`system_dict_*` | 按键和枚举逐项迁移，清理失效配置 | 缓存刷新和枚举兼容 |
| `sys_audit_log` | `system_operate_log`、`system_login_log` | 新操作直接写芋道日志；旧日志只读迁移或归档 | 敏感字段脱敏、可追溯 |
| `sys_file_object`、`sys_file_attachment` | `infra_file*` + 业务附件关系 | 复用文件配置和对象存储，补私有读授权与业务引用 | 跨门店不可越权下载 |
| `sys_async_job` | `infra_job` + 悦指间任务实例表 | 调度配置复用芋道 Job；导入导出进度、租约和结果文件保留业务表 | 重试、幂等、过期清理 |
| `ntf_message*` | `system_notify_*` | 公告、模板和已读关系映射到芋道通知能力，门店范围用扩展关联 | 定向门店、已读状态 |

## 3. 业务模块映射

| 业务域 | main 表/实现资产 | 芋道复用点 | 新系统落点 |
| --- | --- | --- | --- |
| 会员主档 | `mem_member*`、等级、标签、归属历史 | `yudao-module-member` 的会员账号基础能力 | 悦指间会员档案扩展；手机唯一性、归属门店和顾问规则沿用 main |
| 储值/积分/次卡 | `ast_balance_*`、`ast_point_*`、`ast_member_card*`、充值/换卡/转赠/退卡 | member、pay、BPM | 悦指间资产聚合与不可变流水；支付和审批只作为框架，不替代业务账本 |
| 服务与产品 | `cat_category`、`cat_unit`、`cat_service`、`cat_product` | ERP/Mall 主数据模式、代码生成 | 悦指间目录；保留门店上下架、价格快照和服务能力约束 |
| 预约 | `apt_appointment*`、工位、取消原因 | 日历、消息、BPM | 悦指间预约聚合；迁移状态机、员工占用和乐观并发测试 |
| 开单结算 | `trd_bill*`、支付、优惠、资产使用、冲销 | `yudao-module-pay` 渠道/回调/退款框架 | 悦指间交易聚合；混合支付、快照、资产扣减和不可变支付事实保留 |
| 权益 | `cat_voucher`、`ben_voucher_*` | Mall 优惠券模式 | 悦指间券账本；核销与冲销返还跟随账单事务 |
| 提成 | `comm_plan*`、`comm_ledger` | BPM、报表 | 悦指间版本化方案与计提事实；历史账单不得按新方案重算 |
| 回访/客诉 | `vis_visit_*`、`vis_feedback*`、满意度规则 | 消息、BPM | 悦指间客户服务模块；责任人、时限、状态历史和试算规则沿用 main |
| 礼品库存 | `cat_gift`、`inv_stock*`、调拨、盘点 | ERP/WMS 单据和库存模式 | 首轮评审后选择扩展 WMS 或独立悦指间库存；必须保留不可变流水和并发扣减 |
| 配置内容 | 服务小区、首页图片、线上试色、色号素材 | system 配置、infra 文件、AI | 悦指间配置模块；素材私有访问，AI 输入输出待甲方确认 |
| 到家/短信/数据中心 | main 未完成计划 | 地图、消息、报表、BPM | 在核心营业闭环稳定后开发，不能用芋道示例页面标记完成 |

## 4. ID、状态和数据规则

1. 建立迁移批次、步骤、错误、对账和 `legacy_id_map` 等价表；映射键至少包含来源系统、来源表、来源主键、目标表和目标主键。
2. 平台表优先使用芋道生成的新主键；悦指间业务表也不依赖旧主键连续性，所有外键通过映射表转换。
3. 每个状态枚举提交显式对照表；无法确定的旧状态进入错误清单，禁止默认为正常。
4. 金额统一确认单位和精度后转换；未取得真实库样例前，不把 Hibernate 的 `Integer` 或 `Double` 推断为元或分。
5. 会员余额、积分、次卡次数、库存、提成、支付和退款同时做数量、汇总值与流水勾稽对账。
6. 软删除、租户、部门数据范围、审计字段和时间格式按芋道规范写入；历史业务时间不得替换成迁移时间。

## 5. P1 纵向样板顺序

1. 空库导入芋道 SQL Server 基线并验证原生登录、菜单和数据权限。
2. 创建 `yudao-module-yuezhijian`，先落门店扩展和员工档案，不复制 main 通用底座。
3. 完成组织/门店、用户/员工、岗位、角色和权限码字段级映射及种子迁移。
4. 迁移会员等级、标签和会员主档，形成第一个“页面—API—权限—数据库—测试—迁移对账”闭环。
5. 通过总部、门店和普通员工三类账号验证数据范围，再进入会员资产和预约迁移。

P1 完成前不得批量搬运 main Controller 或 Vue 页面；每完成一个纵向模块，都要在新芋道运行入口中验证后更新状态。
