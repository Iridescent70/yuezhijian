# 悦指间系统页面与路由设计

| 项目 | 内容 |
| --- | --- |
| 文档版本 | V1.0 |
| 日期 | 2026-07-29 |
| 设计目标 | 复刻原系统业务内容，重新整理信息架构和交互 |
| 依据 | 两份合同功能清单、旧系统 JSP 页面及 `.do` 入口、`API接口.md` |

旧系统 `customer/charge/oe/item/inv/hr/stat/message/security/fnd/system` 等目录只作为业务参考。新页面不得照搬 iframe、表格套表格和 `.do` 跳转方式；所有路由统一进入 Vue 应用，弹窗、抽屉和页签也必须列入开发及测试范围。

## 1. 前端应用和路由规则

| 应用 | 路由前缀 | 使用人 | 说明 |
| --- | --- | --- | --- |
| PC 管理端 | `/app` | 总部、店长、前台、财务、运营、人事 | 主交付端，Vue 3 管理后台 |
| 员工移动端 | `/m` | 店长、前台、技师 | H5/uni-app，共用同一后端业务接口 |
| 到家客户端 | `/home` | 会员/顾客 | 服务浏览、下单、订单跟踪 |
| 到家店长端 | `/m/home-service` | 店长 | 接单、派单、状态同步 |
| 登录和异常页 | 无统一前缀 | 所有人 | `/login`、`/403`、`/404`、`/500` |

规则：

- 路由 `meta.permission` 对应 API 权限码；按钮还要使用动作权限，前后端双重校验。
- 总部数据范围可切换门店；门店账号不可通过修改 URL 或参数查看其他门店。
- 列表筛选条件、分页和排序同步到 URL query，返回时保留现场；敏感筛选条件除外。
- 编辑类页面离开时若有未保存内容必须二次确认；重复提交按钮在请求完成前锁定。
- 主业务详情使用完整页面；少字段的新建/编辑用弹窗；需要对照历史或较长流程的操作用右侧抽屉。
- PC 最低适配 1366×768；移动端按 375px 设计并适配常见安卓/iOS 宽度。

## 2. 角色和页面可见范围

| 角色 | 默认范围 | 主要页面 | 受限内容 |
| --- | --- | --- | --- |
| 总部管理员 | 全部门店 | 全功能、权限、配置、审计 | 密钥只显示配置状态，不显示明文 |
| 总部运营 | 授权门店 | 会员、营销、经营看板、基础资料 | 无用户安全配置、财务审批 |
| 财务 | 授权门店 | 账单、支付对账、退款、调账、资产、工资 | 会员隐私按字段权限脱敏 |
| 人事/薪酬 | 授权门店 | 员工、借调、提成、工资、目标 | 无会员敏感资产操作 |
| 店长 | 本店 | 工作台、会员、预约、账单、审批、报表、到家 | 不得配置总部级规则 |
| 前台/收银 | 本店 | 会员建档、预约、开单、结算、核销 | 冲销、调账、敏感导出需授权 |
| 技师 | 本人及授权本店 | 今日预约、客户服务档案、回访、业绩 | 工资及他人客户按权限限制 |
| 到家顾客 | 本人 | 服务、技师、下单、本人订单 | 不进入管理端 |

## 3. 公共布局和通用组件

### 3.1 PC 框架

- 左侧：按角色返回的一级/二级菜单，支持折叠和搜索。
- 顶部：当前组织/门店、全局搜索、消息、下载任务、用户菜单；切换当前门店后刷新页面业务上下文。
- 内容区：面包屑、可关闭页签、页面标题、筛选区、主操作区、数据区。
- 右侧全局抽屉：消息中心、下载中心、最近操作、待审批事项。
- 工作台快捷入口默认包含新建会员、新建账单、新建预约、会员查询、结账查询、预约查询、积分兑换、代金券兑换、服务码核销。

`UI-AST-003`首版同样合入会员资产页：通过手机号、会员号或会员卡号检索正常会员，确认接收人、转赠后有效期、经办员工和原因后整体转移剩余次数。原卡立即失效，新卡号在成功提示中返回。

`UI-MEM-003`已补资料、状态和标签维护。手机号编辑框不展示原号码，留空即保持原值；冻结后详情显示原因和时间，冻结会员已被现有开单及资产服务拒绝。标签弹窗只读取启用标签，不在会员详情里临时创建标签。详情页提供“调整归属”入口并携带会员上下文跳转`UI-MEM-009`。`UI-MEM-007`标签规则配置页和`UI-MEM-010`独立冻结历史页仍为后续范围。

`UI-MEM-001`已增加当前页勾选和三项批量操作。冻结必须填写原因；标签可以同时添加和移除但同一标签不能出现在两边；分配顾问只允许选择同一归属门店的会员。完成后弹窗分别显示成功、跳过和失败记录，不能只给一个“操作成功”提示掩盖部分失败。当前每页最多100人，跨页客群批处理等任务中心落地后再开放。

`UI-MEM-009`按审批状态和执行状态查询申请。新申请先搜索会员，明确展示当前门店，只能选择其他启用门店；生效日期不得早于今天。审批通过后页面分别显示“待生效”或“已生效”，驳回必须填写原因。分润规则以JSON对象快照展示，未确认时使用`{}`，页面不提供虚构比例或计算结果。

### 5.1 会员详情页固定结构

会员详情不能把旧系统全部字段平铺在一个表单，按以下页签组织：

1. `概览`：等级、余额、积分、次卡、累计消费、到店次数、最后到店、标签、冻结/特殊提示。
2. `基础档案`：联系方式、生日、来源、归属门店、顾问、消费归属关系；编辑抽屉。
3. `会员资产`：储值、积分、次卡、券；每类均可展开流水和源单。
4. `消费记录`：账单、服务项目、产品、技师、消费归属，支持跳转账单。
5. `服务档案`：偏好、禁忌、常用色号、咨询卡、服务照片和历史版本。
6. `预约与回访`：预约时间线、爽约次数、待回访和已完成记录。
7. `跟进记录`：聊天式记录、负向提示、附件、创建人和时间。
8. `AI 建议`：标签、复购/流失提示和推荐；必须显示依据、生成时间、采用/驳回按钮。

右侧固定快捷操作为新建预约、快速充值、创建账单、发券、发短信；按钮按权限隐藏。

## 13. UI 状态和人工审核清单

每个页面设计图至少包含以下状态，不能只交付一张正常态：

1. 初始/空数据、加载中、加载失败、无权限、数据不存在。
2. 正常列表、筛选后无结果、分页、排序、超长文本、敏感字段脱敏。
3. 表单首次打开、校验错误、保存中、并发冲突、保存成功。
4. 状态不允许、余额/积分/次数/库存不足、第三方失败、重复提交。
5. 1366×768 PC 和 375px 移动宽度；表格横向滚动和固定操作列。

人工审核按批次进行：

- 第一批：登录、工作台、会员列表/详情、预约排期、创建账单、结算。
- 第二批：次卡全生命周期、调账/冲销、回访、基础资料、权限。
- 第三批：报表/数据中心、薪酬、短信、到家、移动端、AI。

页面审核通过标准：内容与原系统业务一致、符合合同功能、所有按钮和弹窗齐全、字段与 API/数据库能对应、异常状态明确。审核结论记录“通过/修改后通过/不通过”，未通过页面不得直接作为开发完成项。

## 14. 页面完成定义

一个页面只有同时满足以下条件才可标记完成：路由可访问、权限正确、正常和异常状态齐全、弹窗/抽屉已实现、接口已联调、操作有明确反馈、审计可查、主流分辨率通过、对应功能清单用例通过。静态页面、写死数据或只完成主列表都不算完成。
