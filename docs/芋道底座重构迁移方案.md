# 悦指间基于芋道全栈底座的重构迁移方案

更新时间：2026-07-30。

## 1. 目标与基线

本次重构以芋道完整单体版为新的运行底座，同时继承 `main` 已实现的业务规则、测试、数据库设计和未完成功能计划。不是在旧自研后端上套一层芋道页面，也不把芋道示例功能直接当作悦指间业务完成。

| 范围 | 基线 |
| --- | --- |
| 业务基线 | `main@6cae2c8`，`ITER-00` 至 `ITER-52` 的实现与记录 |
| 后端底座 | `YunaiV/ruoyi-vue-pro`，`master-jdk17@ec3f7cb` |
| 前端底座 | `yudaocode/yudao-ui-admin-vue3`，`master@9445977` |
| 重构分支 | `refactor/yudao-foundation` |
| 数据库 | SQL Server 2022；芋道基线 SQL + 悦指间 Flyway 增量 |
| 认证协议 | 芋道 Spring Security Token + Redis，管理端统一 `/admin-api` |

后端选择完整版而不是 mini：悦指间后续明确需要会员、审批、支付、报表、ERP/WMS 等能力，完整版已经包含对应模块源码；当前启用 `system`、`infra`、`member` 和悦指间业务模块，其余模块按迁移范围逐个启用。

## 2. 资产保留和目录边界

- `backend/`：新的芋道单体后端，后续悦指间服务端功能只在这里开发。
- `frontend/`：新的芋道 Vue3 管理端，后续 PC 页面只在这里开发。
- `ref/main-backend-snapshot/backend/`：`main@6cae2c8` 自研后端完整快照，包含业务实现、测试和 44 个历史 Flyway 脚本，只读参考。
- `ref/main-frontend-snapshot/`：main 自研 Vue 前端快照，只读参考。
- `docs/`、`plan/`、`memory/`：合同范围、设计、迭代记录和业务决策，全部保留并随迁移校正状态。
- `ref/legacy-source/`：甲方多年以前的 Java 6/Struts/Hibernate/JSP 源码，只保存在本地并由 Git 忽略。

迁移时的规则优先级为：甲方书面确认与真实数据 > 两份合同清单 > 已冻结业务决策和测试 > main 快照实现 > 甲方旧源码行为 > 芋道示例规则。

## 3. 架构原则

1. 保持前后端分离、模块化单体和单仓库，不在首轮拆微服务。
2. 直接复用芋道用户、角色、部门、岗位、菜单、数据权限、字典、日志、文件、任务、通知和代码生成基础设施。
3. 悦指间业务进入独立业务模块，禁止直接把大量定制逻辑堆进 `system` 或 `infra`。
4. 前端使用芋道原生 Token、动态路由、字典和响应结构，不再维护旧 Spring Session/CSRF 兼容层。
5. 芋道 SQL Server 官方脚本只用于全新数据库的一次性基线导入；共享环境禁止重复执行。基线之后只允许新增 Flyway 版本脚本。
6. main 的 44 个迁移脚本不直接在芋道库重放；先做表和字段映射，再把需要保留的数据结构转换成新的增量迁移。
7. 资金、储值、积分、次卡、库存、提成、退款和冲销仍遵循 main 已冻结的状态机、快照和不可变流水规则。

## 4. 复用与迁移映射

字段、ID、权限和实施顺序的详细基线见[《芋道模块与数据迁移映射》](../plan/migration/芋道模块与数据迁移映射.md)。

| 悦指间范围 | 芋道复用点 | 迁移策略 |
| --- | --- | --- |
| 登录、用户、角色、菜单、权限 | `system` 模块、Token、动态路由、数据权限 | 直接复用；把门店组织和权限码映射到芋道模型 |
| 门店、员工、职务 | 部门、用户、岗位、数据范围 | 复用通用模型；补充门店切换、隐私字段和业务归属规则 |
| 字典、参数、日志、通知 | `system` 字典/配置/日志/站内信 | 优先直接复用，迁移旧配置与历史数据 |
| 文件、任务、导入导出 | `infra` 文件、Job、API 日志、代码生成 | 复用平台能力；补齐私有文件鉴权、租约与保留期要求 |
| 会员、等级、标签 | `member` 模块 | 启用后扩展悦指间主档、归属、储值、积分和次卡资产 |
| 审批 | `bpm` 模块 | 退卡、冲销、赔付等新流程优先接 BPM；历史审批事实保留 |
| 支付、退款 | `pay` 模块 | 复用渠道、回调、订单和退款框架；混合支付与资产扣减定制 |
| 产品、服务、库存 | `erp`、`wms`、Mall 商品能力 | 复用主数据和单据模式；门店价格、礼品库存和流水按业务扩展 |
| 报表、数据中心 | `report`、ECharts、大屏 | 复用展示与设计器；指标、权限和脱敏口径重新验收 |
| 预约、开单、回访、提成、到家 | 通用表单、日历、BPM、地图、消息 | 建立悦指间业务模块，迁移 main 状态机和测试 |
| 在线试色、AI 推荐 | 文件、富媒体和 AI 模块 | 甲方先确认输入输出与验收口径，再按需启用 |

## 5. 分阶段执行

### P0：全栈底座可构建

- 从 main 建立独立重构分支，保存原前端和原后端快照。
- 通过 Git subtree 导入同批次芋道前后端并记录上游提交。
- 恢复 `/admin-api`、Token、Redis、动态菜单和字典原生协议。
- 建立 SQL Server + Redis 本地环境、安全的 `yuezhijian` profile、一次性基线导入和 Flyway 增量入口。
- 完成 Maven、pnpm、CI、类型检查与生产构建基线。

### P1：平台模型和首个纵向样板

1. 初始化芋道 SQL Server 数据库，验证登录、退出、刷新 Token、菜单、按钮权限和操作日志。
2. 定义门店与芋道部门/数据权限的映射，完成总部和门店账号数据范围。
3. 建立 `yudao-module-yuezhijian` 业务模块及 API/实现分层。
4. 迁移“门店—员工—岗位—会员主档”纵向样板，同时迁移 main 对应回归测试。
5. 建立旧 ID 到新 ID 的映射、迁移批次和对账表。

### P2：迁移 main 已实现业务

按依赖与风险依次迁移：

1. 主数据、会员、标签、归属、储值、积分、次卡、代金券。
2. 预约、开单、混合结算、优惠、冲销、换卡、转赠和退卡。
3. 产品、服务、礼品库存、调拨、盘点、支付方式和操作历史。
4. 提成、回访、客诉、通知、文件、异步任务和下载中心。
5. 首页图片和线上试色。

每项必须同时迁移接口、页面、权限、门店范围、并发保护、数据脚本和测试；“源码已经复制”不算完成。

### P3：完成合同未开发范围

- 积分兑换与库存原子扣减。
- 服务档案、咨询卡、常用色号和赔付审批。
- 完整薪酬规则、多人分配、店长提成和工资单。
- 短信任务、回调和生日/到期/日报等自动通知。
- 到家订单、派单、技师端和客户端。
- 统计分析、数据中心和甲方确认后的 AI 推荐。

### P4：数据迁移和上线

- 获取甲方旧库备份，完成表字段盘点、金额单位确认、清洗和 ID 映射。
- 至少执行一次全量试迁移、一次增量演练和逐项数量/余额/流水/账单/支付对账。
- 完成安全基线、性能、备份恢复、灰度、回滚、停机窗口和最终签字。

## 6. 数据库演进

1. 新空库执行 `backend/sql/sqlserver/ruoyi-vue-pro.sql` 建立芋道基线；`make db-init` 用标记表防止重复覆盖。
2. 应用首次启动由 Flyway 对既有基线执行 baseline，并从 `V202607300000` 开始管理悦指间增量。
3. 旧库始终只读；迁移程序按“源读取—转换—目标写入—对账”工作，不允许业务代码跨库实时拼接新旧数据。
4. 已在共享环境执行的 Flyway 文件禁止修改；修复必须新增更高版本。
5. 上游升级如果包含数据库变化，先人工转成新的悦指间 Flyway 脚本并验证，禁止直接重跑上游全量 SQL。

## 8. 验收底线

- 新系统是否完成以芋道运行入口中的真实功能和测试为准，main 快照中的 DONE 只表示有可迁移资产。
- 未迁移模块不得通过示例菜单、假统计或上游演示数据冒充完成。
- 金额、余额、积分、次卡、库存、提成、退款必须保留不可变事实并可对账。
- 权限必须同时验证功能权限、门店数据范围和敏感字段保护。
- 甲方数据库备份、金额单位和关键口径未确认前，只记录风险和 TODO，不猜测定稿。
