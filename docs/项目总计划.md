# 悦·指间管理系统项目总计划

| 项目 | 内容 |
| --- | --- |
| 版本 | V2.8 |
| 周期 | 2026年7月29日—2026年8月28日 |
| 依据 | 两份合同功能清单、原系统、甲方源码及双方书面确认的变更 |

## 一、项目目标和范围

1. 参考甲方源码和原系统，重构“悦·指间美甲管理系统”92项合同功能。
2. 完成“悦指间门店管理系统”47项优化及新增功能。
3. 完成合同约定范围内的10%需求变更，变更内容须由双方书面确认。
4. 将AI分析推荐接入新系统，AI异常时不能影响开单、结算等正常业务。
5. 将老系统业务数据迁到新系统，完成上线、业务陪跑和项目交付。

两份合同清单共139项。其中5项“数据中心”还缺少详细内容，须在7月31日前补齐。

## 二、源码结论和开发方式

7月29日已将甲方源码解压到本地参考目录。初步检查结果如下：

| 已确认情况 | 对项目的影响 |
| --- | --- |
| 解压后约4691个文件，其中JSP页面1021个，并包含大量业务JAR和Hibernate映射 | 可以用于整理页面、操作入口、旧接口和数据表关系 |
| 原系统为Java 6、Struts、Spring、Hibernate、SQL Server的老式Java Web系统，前端使用JSP、jQuery和DWZ | 技术栈过旧，不直接复制到新系统 |
| 主要业务代码已编译在JAR/Class中，未发现完整构建文件 | 这份资料属于部署包，不是可以直接编译修改的完整源码工程 |
| 压缩包末尾损坏，缺少`web.xml`、部分框架依赖和启动配置 | 当前无法完整启动，须补交完整压缩包或确认以现有资料为准 |
| 配置文件中保留了历史数据库及第三方接入信息 | 只能用于识别接口，旧账号和密钥一律停用并重新申请 |

因此，旧源码只用于还原功能和数据关系，不作为新系统的代码底座。齐总版和钇休版需要实际运行比较后选定一个主版本；新开发代码不得继续依赖旧系统的JAR和Class。

实际执行顺序为：

**合同功能清单 → 对照旧JSP、Action和数据映射 → 页面清单、API表、数据库映射 → UI人工确认 → 在主重构版本上开发 → AI检查 → 燃燃业务测试 → 新增优化和AI接入 → 数据迁移 → 上线交付**

开发由AI完成，人工负责需求确认、UI审核、数据库关键规则确认、业务测试和最终验收。

## 六、完成和交付标准

1. 92项重构、47项优化及双方确认的10%变更全部开发并测试通过。
2. 新系统可独立构建和部署，不依赖旧系统的JAR、Class及历史服务器目录。
3. AI分析推荐可以正常使用，服务异常不影响门店业务。
4. 老系统需保留的数据全部迁移，会员余额、积分、次卡、账单和支付等关键数据对账一致。
5. 旧账号和密钥全部替换，新系统配置不在代码和Git仓库中保存明文凭据。
6. 燃燃完成两轮测试和上线陪跑，核心营业流程可以正常使用，阻断和严重问题为0。
7. 召开交付会议，移交源码、数据库脚本、部署资料、接口文档、测试及迁移报告、操作手册，并形成双方确认的验收记录。

未完成内容须在交付记录中写明负责人和完成日期，不能直接标记为项目整体完成。
